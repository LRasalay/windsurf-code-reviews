6sGiven that we are in Risk management and Anti Money Laundering - How to ensure engineers understand intent based development quicklyEnsuring Engineers Understand Intent-Based Development Quickly in Risk Management and AML Contexts
Intent-based development (IBD) refers to a paradigm where software engineers specify high-level intents or requirements (e.g., via natural language prompts or specs) and leverage AI tools to generate, refine, or automate code implementation. This is particularly relevant in regulated domains like Risk Management and Anti-Money Laundering (AML), where code must align with compliance rules, fraud detection logic, and risk assessment models while minimizing errors. Tools like GitHub Copilot, Windsurf, and Claude Code enable this by translating intents into secure, auditable code—e.g., "Implement a transaction monitoring system that flags patterns indicative of money laundering per FATF guidelines."
In banking, IBD accelerates development while ensuring traceability for audits, but engineers may need rapid upskilling to shift from traditional coding to intent-driven workflows. Below, I'll outline strategies to facilitate quick understanding, tailored to AML/Risk teams. These can be integrated into your Developer Enablement OKRs, building on quicker onboarding and local setups.
1. Define and Contextualize IBD with Domain-Specific Examples

Why it works: Engineers learn faster when concepts are tied to familiar problems, reducing cognitive load.
How to implement quickly:
Start with a 1-hour intro session: Explain IBD as "prompting AI like Copilot to handle boilerplate while you focus on risk logic."
Use AML examples: "Intent: Detect layering in transactions over $10K with multiple accounts. AI Output: Generated Python code using pandas for pattern matching, integrated with compliance APIs."
Provide cheat sheets: Prompts like "Generate AML alert rules in SQL for high-risk jurisdictions" with before/after code comparisons.

Timeline: Roll out in week 1 of onboarding; aim for 80% comprehension via quick quizzes.

2. Hands-On Workshops and Interactive Simulations

Why it works: Practical application reinforces understanding 2-3x faster than lectures, especially for technical teams.
How to implement quickly:
Set up 2-3 hour workshops using local tools (e.g., Windsurf's standalone app for offline prototyping).
Scenarios: Engineers input intents like "Build a risk scoring model for PEP screening" into Claude Code, then refine outputs for accuracy.
Pair programming: Senior devs mentor juniors on iterating prompts to ensure outputs comply with regulations (e.g., avoiding biases in ML models for fraud detection).
Tools integration: Use Copilot in VS Code for real-time feedback on AML-specific code (e.g., integrating with Napier AI or similar for transaction analysis).

Timeline: Conduct bi-weekly; track via post-workshop feedback (target NPS > 7/10).

3. Leverage AI for Personalized Learning Paths

Why it works: AI adapts to individual gaps, speeding up mastery in complex areas like AML where understanding intent (e.g., regulatory nuances) is key.
How to implement quickly:
Use Claude Code or Windsurf to assess baselines: Prompt AI with "Quiz on IBD for AML: Generate 5 questions on prompt engineering for risk models."
Generate tailored modules: E.g., for a dev weak in compliance, AI creates paths like "From intent to code: Implementing KYC checks with AI assistance."
Integrate into local setups: One-click installs allow offline practice on sample datasets (e.g., anonymized transaction logs for money laundering simulations).

Timeline: Automate during onboarding day 1; review progress in 30/60/90-day plans.

4. Incorporate Metrics and Feedback Loops

Why it works: Measurable progress motivates quick adoption and identifies blockers early.
How to implement quickly:
Track understanding: Metrics like "Time to generate compliant code from intent" (target: <30 min after training) or "% of PRs using IBD workflows."
Feedback tools: Use surveys or AI chats (e.g., via Glean) post-task: "Did you understand how to specify intents for this AML feature?"
Align with Risk/AML: Ensure examples cover high-stakes areas like SAR filing automation, with human reviews to mitigate AI risks (e.g., hallucinations in rule interpretations).

Timeline: Monitor weekly; adjust based on data (e.g., if comprehension is low, add more examples).

5. Address Domain Challenges and Best Practices

Key considerations for Risk/AML:
Compliance Focus: Train on "safe intents" that embed regulations (e.g., prompts including "Ensure GDPR compliance in data handling").
Risk Mitigation: Emphasize human oversight—AI generates, but engineers validate for accuracy in sensitive areas like false positives in laundering detection.
Scalability: Start small with non-production pilots (e.g., intent-based updates to risk dashboards) to build confidence.

Resources: Draw from industry insights like McKinsey's gen AI for risk/compliance or EY's AI in banking risks for real-world case studies.

14.3s10 sourcesCreating standardized PRDs to understand intent to speed up delivery and what are the ways to improve discovery timeCreating Standardized PRDs to Understand Intent and Speed Up Delivery
In the context of Risk Management and Anti-Money Laundering (AML) development at a large US bank, standardized Product Requirements Documents (PRDs) serve as a blueprint to clearly capture stakeholder intent—such as regulatory compliance needs, risk scoring logic, or fraud detection workflows. By formalizing intents (e.g., "Flag transactions exceeding $10K with unusual patterns per FATF guidelines"), PRDs reduce ambiguity, align teams, and accelerate delivery in intent-based development workflows. This is especially valuable when integrating AI tools like GitHub Copilot or Claude Code, where clear intents translate directly into code generation. Standardized PRDs can cut miscommunication by 20-30%, leading to faster iterations and fewer rework cycles in regulated environments.
Steps to Create Standardized PRDs
Follow these best practices to build consistent, actionable PRDs. Use templates to ensure uniformity across projects, and leverage AI to automate drafting for quicker turnaround.

Define Structure and Template:
Adopt a modular format: Split into high-level product proposals (vision, goals, user needs) and detailed feature proposals (specs, acceptance criteria).
Key sections: Overview (problem statement, objectives), User Personas (e.g., risk analysts in AML), Requirements (functional/non-functional, with intent phrased as user stories), Success Metrics (e.g., reduced false positives by 15%), Risks/Dependencies (regulatory approvals), and Appendices (wireframes, data models).
For banking: Include compliance mappings (e.g., SOX, FDIC alignment) to embed regulatory intent early.

Gather and Clarify Intent:
Conduct stakeholder workshops to elicit intents via questions like "What outcomes do we need for transaction monitoring?"
Translate user needs into verifiable requirements: E.g., from "Detect money laundering" to "System must flag 95% of high-risk patterns using ML models."
Use AI: Tools like ChatPRD or Copilot4DevOps can generate initial drafts from prompts like "Create a PRD for an AML risk scoring tool based on these user stories." This can reduce drafting time by 50-70%.

Review and Iterate:
Involve cross-functional teams (engineers, compliance officers) for feedback loops.
AI-assisted reviews: Use Claude Code to validate intents against code feasibility or Windsurf to simulate workflows.
Version control: Store in tools like Jama Connect for traceability.

Integrate with AI-Driven Development:
Phrase requirements as intents for direct AI input: E.g., feed PRD sections into Copilot for spec-to-code generation.
Benefits: Speeds delivery by automating boilerplate, ensuring code aligns with AML intents like audit trails.


Benefits for Speeding Up Delivery

Clarity on Intent: Reduces scope creep; teams understand "why" behind features, enabling faster prioritization.
Efficiency Gains: Standardized formats cut PRD creation from days to hours with AI, leading to 20-40% faster dev cycles in agile setups.
In Regulated Contexts: Ensures compliance is baked in, avoiding late-stage audits that delay releases.

Ways to Improve Discovery Time
The discovery phase—gathering insights on user needs, market fit, and feasibility—typically lasts 4-8 weeks but can be compressed to 2-4 weeks with focused techniques. In Risk/AML, this means quicker validation of ideas like new fraud models. Here are proven methods, emphasizing AI to align with your developer enablement goals.
1. Streamline Research and Interviews

Conduct targeted customer interviews: Observe users (e.g., AML analysts) in action to identify pain points quickly, rather than broad surveys.
AI Boost: Use tools like UserVoice or AI chatbots to automate interview scheduling and sentiment analysis, cutting prep time by 30%.

2. Leverage Structured Frameworks

Adopt Opportunity-Solution Trees: Map user problems to opportunities, then brainstorm solutions collaboratively—shifts focus from delivery to value.
Include in Roadmaps: Evangelize discovery's importance to secure dedicated time; empower engineers to own parts like tech feasibility checks.
AI Integration: Prompt AI (e.g., Claude) with "Generate an Opportunity Tree for AML transaction monitoring" to visualize ideas rapidly.

3. Incorporate AI and Automation Tools

AI for Insight Generation: Use generative AI to synthesize data from user feedback or market research into initial hypotheses, reducing manual analysis.
Rapid Prototyping: Tools like Windsurf can create low-fidelity mocks from intents, validating concepts in days.
Data-Driven Discovery: Analyze internal logs (e.g., past AML alerts) with AI to uncover patterns without lengthy studies.

4. Foster Collaboration and Iteration

Cross-Functional Workshops: Involve devs, designers, and compliance early to parallelize efforts.
Metrics for Speed: Track discovery KPIs like "time to validated hypothesis" (target: <2 weeks) and iterate based on feedback.
Banking Tip: Prioritize high-impact areas like regulatory changes; use AI to scan for updates (e.g., via semantic search) to preempt delays.

By combining standardized PRDs with these discovery improvements, you can enhance intent understanding, reduce discovery from weeks to days, and boost overall delivery in your OKRs.
